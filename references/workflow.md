# 旅游活动物料生成工作流

本文档用于沉淀旅游垂类节点活动物料的 AI agent 执行流程。目标是让 agent 从一句活动需求开始，完成风格发散、视觉发散、母版设计和全套物料适配。

## 1. 需求输入解析

用户通常会输入类似“毕业旅行季”“夏日出游季”“国庆自驾游活动”这样的短需求。

agent 需要优先解析以下信息：

| 字段 | 说明 | 是否必须 |
| --- | --- | --- |
| 活动主题 | 用户输入的核心活动名称或营销主题 | 必须 |
| 目标人群 | 学生、亲子、年轻人、情侣、家庭、自驾用户等 | 可推断 |
| 时间节点 | 春节、暑期、毕业季、国庆、周末等 | 可推断 |
| 目的地 / 场景 | 城市、公园、海边、山野、乐园、古镇等 | 可推断 |
| 情绪关键词 | 松弛、热闹、青春、治愈、探索、仪式感等 | 可推断 |
| 商业目标 | 引导点击、活动报名、优惠转化、品牌曝光等 | 可推断 |
| 用户补充要求 | 指定风格、指定文案、指定元素、无需询问等 | 用户输入优先 |

如果用户没有额外输入，agent 应尽可能自我判断；如果用户有明确补充，必须以用户输入为准。

## 2. approval_mode 全局拍板模式

首次需求输入阶段需要判断是否进入自动模式。

```text
approval_mode:
  ask_user  默认模式，关键节点需要询问用户拍板
  auto      用户明确表示无需询问，agent 自动推进
```

触发 `auto` 的常见表达：

- 无需询问
- 不用问我
- 你来定
- 自动决定
- 直接做
- 直接输出

规则：

- `approval_mode` 在首次需求解析阶段确定。
- 后续风格拍板、视觉拍板、母版确认、终稿确认都继承该模式。
- 用户中途说“我来选 / 先别自动”时，切回 `ask_user`。
- 用户中途说“你定 / 不用问我”时，切到 `auto`。
- 即使在 `auto` 模式下，agent 也必须记录自动选择的编号和理由。

## 3. 风格发散阶段

目标：决定“用什么风格”，并让用户看到该风格套用到当前主题后的大致效果。

默认生成 3-5 个风格方向。风格方向应从风格库中选择，而不是凭空发明。每个候选风格需要生成 1 张当前主题的风格预览图。

当前风格类型：

- 手帐拼贴风
- 电商大字报风
- 电影实景风
- 运营3D风
- 手绘风
- 微软风
- 新中式

输入：

- 用户原始需求
- 需求解析结果
- 风格库参考图
- 用户指定风格，如有

输出：

- 3-5 个候选风格方向
- 每个方向的风格库参考依据
- 每个方向 1 张主题化风格预览图
- 每个方向引用的风格库参考图路径或目录
- 每个方向的简短推荐理由

规则：

- 如果用户指定某个风格，只围绕该风格继续，不再生成 3-5 个风格方向。
- 如果用户没有指定风格，默认选择 3-5 个最匹配的风格方向。
- 风格选择要考虑活动主题、人群、节日情绪、旅游场景和商业目标。
- 风格库原图只能作为参考依据，不得直接作为候选风格展示图。
- 候选风格展示图必须是基于当前活动主题生成的位图预览，需要包含真实主标题或明确主题信息。
- 在 `ask_user` 模式下，必须先展示全部主题化风格预览图和推荐理由，等待用户选择 1 个风格后，才进入视觉发散。
- 在 `auto` 模式下，agent 可自动从 3-5 个候选风格中选择 1 个风格，但必须记录自动选择编号和理由，然后只基于该风格进入视觉发散。
- 风格发散阶段只用于决定风格，可以生成每个候选风格的主题化预览图，但不生成 5 个视觉方向，不生成视觉探索图。
- 主题化风格预览图必须使用 ChatGPT Image 2 / image2.0 生成真实位图，禁止用 SVG、HTML、CSS、canvas、JS 绘图脚本替代。

## 4. 视觉发散阶段

目标：在已确定的单一风格下，探索“具体画面怎么做”。

默认数量：

```text
1 个已选风格 × 5 个视觉方向 = 5 张探索图
```

禁止：

```text
一次性跨多个风格输出 15 张探索图
```

不得跨多个风格一次性生成视觉探索。本阶段只能围绕已确定的 1 个风格输出 5 张探索图。

每个视觉方向需要探索的变量：

- 主视觉构图：人物、风景、图形、产品化卡片、拼贴、场景叙事等
- 核心元素：目的地、人物、交通、季节物、符号元素等
- 色彩倾向
- 字体气质
- 标题层级
- 画面节奏：安静、热闹、强促销、电影感、松弛感等

输出：

- 5 张探索图
- 已选风格方向说明
- 每张图的风格方向说明
- 每张图的视觉方向说明

生成要求：

- 探索图必须是由 ChatGPT Image 2 / image2.0 生成的真实位图视觉稿。
- 输出格式应为 PNG 或 JPG。
- 禁止用 SVG、HTML、CSS、canvas、JS 绘图脚本或其他代码绘制方式替代探索图。
- 禁止只输出文字规划、线框图、缩略占位图或矢量卡片。
- 如当前环境无法调用图像生成能力，应停止并说明无法生成图片，不要伪造视觉稿。

## 5. 方案编号规则

探索图使用简单编号，方便用户输入。

```text
风格编号.视觉编号
```

示例：

- `1.1` = 第 1 个风格方向下的第 1 个视觉方案
- `1.5` = 第 1 个风格方向下的第 5 个视觉方案
- `2.3` = 仅当用户先选择第 2 个风格方向时，表示该风格下的第 3 个视觉方案
- `3.5` = 仅当用户先选择第 3 个风格方向时，表示该风格下的第 5 个视觉方案

用户可输入：

- `2.3`：选择单张方案
- `2.3 + 2.4`：融合同一已选风格下的两个视觉方向
- `2.3构图 + 2.2色彩 + 2.1字体`：在同一已选风格下局部融合
- `都不行`：重新发散
- `你定`：agent 自动选择并记录理由

## 6. 拍板或自动选择

在 `approval_mode = ask_user` 时：

- 展示所有探索图。
- 给出 agent 推荐排序。
- 询问用户选择编号。
- 支持用户选择单一方案或多方案融合。

在 `approval_mode = auto` 时：

- agent 自动选择最优编号。
- 记录选择理由。
- 直接进入母版设计阶段。

拍板结果需要记录：

- 选择编号
- 是否融合多个方案
- 融合规则，如构图、色彩、字体、元素分别来自哪里
- agent 推荐理由
- 用户最终反馈，或自动选择理由

## 7. 横版母版设计阶段

目标：从选定探索图沉淀一个可复用的横版主视觉母版。

母版必须基于已选探索方向继续用 ChatGPT Image 2 / image2.0 生成位图，不得改用 SVG、HTML、CSS、canvas 或 JS 脚本绘制。

母版定义：

- 默认横版。
- 必须带真实主标题，不做空画面。
- 可以包含副标题、利益点、活动标签、按钮、二维码等模块。
- 后续多尺寸适配以该母版作为统一视觉来源。

输入：

- 选定方案编号
- 融合规则，如有
- 用户原始需求
- 主标题 / 副标题 / 活动信息，如有
- 风格库参考图

输出：

- 横版母版图
- 主标题文案
- 副标题 / 利益点文案
- 背景、主体、装饰元素说明
- 字体气质
- 色彩体系
- 版式结构
- 可隐藏模块清单

确认规则：

- `approval_mode = ask_user`：展示母版，询问用户确认。
- `approval_mode = auto`：agent 自动确认，记录理由。

## 8. 多尺寸适配阶段

目标：将横版母版适配为全套固定物料尺寸，而不是每个尺寸重新设计。

固定尺寸规则见：

- `references/material-spec.md`

适配策略分三类：

| 类型 | 说明 |
| --- | --- |
| 同比例缩放 | 接近母版比例，保留完整构图 |
| 重构排版 | 比例差异大，如竖版、方图，需要重新安排标题和主体 |
| 模块裁剪 | 小尺寸只保留主标题、核心视觉和品牌信息，隐藏次要利益点 |

适配时需要记录：

- 母版文件
- 目标物料名称
- 目标尺寸
- 安全区要求
- 保留元素
- 隐藏元素
- 适配策略
- 输出文件

## 9. 安全区检查

每个尺寸输出后必须检查：

- 主标题是否进入安全区
- 核心人物面部是否进入安全区
- Logo 是否进入错误区域
- 按钮、二维码、利益点是否贴边
- 小字号是否可读
- 元素是否互相遮挡
- 背景是否可以延展到出血区域

通用规则：

- 安全区限制关键元素，不限制低信息背景和氛围装饰。
- 标注“呼吸空间”的区域不放高密度文字、小字号信息、人物面部、按钮或二维码。
- 标注“无”的物料仍需默认保留四周 5% 基础边距。
- 小尺寸物料优先保留主标题、核心视觉和品牌识别。

## 10. 最终交付

最终交付应包含：

- 横版母版
- 全套适配图
- 微信公众号拼接交付图，如涉及
- 输出清单
- 自动检查结果
- 用户确认结果，或自动确认理由

微信公众号特殊交付：

- 先分别生成 `1280 × 545 px` 横图和 `545 × 545 px` 方图。
- 再拼接为 `1825 × 545 px` 最终交付图。
- 左侧为横图，右侧为方图。
- 横图与方图高度一致，拼接后不应出现额外留白区域。

## 11. 返工分支

用户反馈可能触发返工：

| 用户反馈 | 处理方式 |
| --- | --- |
| 风格不对 | 回到风格发散阶段 |
| 画面不对 | 回到视觉发散阶段 |
| 构图可以但细节不对 | 回到母版设计阶段局部修改 |
| 某个尺寸不好 | 只重做对应尺寸适配 |
| 都不满意 | 回到需求解析，重新判断方向 |

返工时不得丢失用户已确认的信息。
